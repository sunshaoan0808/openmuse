# 凭据与沙箱计划

> 背景：挖完 Muse 的 Confidential VM 体系（见 `docs/muse-原版挖掘记录.md` §12）后，用户点名要做三件：
> ① 凭据的 App 管理页 ② 任务级凭据真正接给工具用 ③ 沙箱"任务结束即重置"。
> 本文是这三件的落地计划：每件都写清**现状（带证据）→ 做法（文件级）→ 验收（怎么证明）→ 风险**。
>
> 已有的底座（本轮已完成、已实测）：
> - `apps/server/src/credentials.ts`：`mintCredential` / `listCredentials`（**只回后 6 位**）/ `revokeCredential`
>   / `revokeForTask` / `sweepExpired` / `resolveSecret`（失效时给可续接提示，对应 Muse 的 `StoredCredentialContinuation`）
> - 路由：`GET·POST /api/agent/credentials`、`POST /api/agent/credentials/:id/revoke`
> - **任务终态钩子**：`service.publishOutcome` 里调 `revokeForTask` —— 实测任务 `succeeded` 后凭据 `revokeReason=task_finished`
> - `packages/domain`：`TemporaryCredential{id,label,kind,scopes,taskId,createdAt,expiresAt,revokedAt,revokeReason}`

## ① 凭据的 App 管理页

**目标**：用户能看见"我有哪些短时凭据、绑在哪个任务、什么时候销毁"，并能立刻吊销。

**现状（证据）**
- 只有 API：`GET /api/agent/credentials` 已返回掩码后的列表（`secretTail`、`usable`、`revokeReason`）
- App 侧**没有任何界面**：`grep -rn "credentials" apps/mobile/src/*.tsx` 无命中
- 可复用组件齐备：`src/ui.tsx` 的 `Card / Chip / Button / Empty / Sheet / SectionHeading`
- ⚠️ 注意：`/api/agent` 快照里**不含** credentials，界面要自己 `api.request("/api/agent/credentials")`

**做法（文件级）**
1. `apps/mobile/src/agent-ui.tsx` 新增 `CredentialsScreen`：
   - 列表行：`label` + `kind` 标签 + `scopes` + 绑定任务（可点进任务详情）+ 到期时间 + 状态 Chip
     （`可用` 绿 / `已销毁` 灰 / `已过期` 灰，文案取自 `revokeReason`）
   - **只显示 `secretTail`**；任何地方不出现明文（沿用项目铁律）
   - 每行「立即吊销」→ `mutate("/credentials/:id/revoke", {})`
   - 顶部「铸一把」→ `Sheet` 表单（label / kind=git·api·ssh / scopes / TTL / 可选绑定任务）
     → 铸完**一次性**显示明文 + 「复制」按钮 + 明确提示"只显示这一次，离开即不可见"
2. 入口：放进「应用」页（`screens.tsx` 的 `ConnectionsScreen`）的一个分区，**不加第 6 个底部导航项**
3. 文案全部中文；状态词表进 `src/labels.ts`

**验收**
- 铸一把 → 列表出现、**只显示后 6 位**；关掉重进仍是掩码（截图）
- 点吊销 → 状态变「已销毁」、`usable=false`
- 铸的那一刻明文可复制；刷新后**再也取不到**

**风险**：明文只显示一次容易被用户吐槽"没存下来" → 文案必须写清；不做"再看一次"（那等于留后门）。

**工作量**：半天。

## ② 任务级凭据真正接给工具用

**目标**：任务需要写仓库/调外部 API 时，用的是一把**只在这次任务期间有效、任务结束即销毁**的凭据，
而不是 `.env` 里的长期 key。

**现状（证据）**
- `resolveSecret(db, owner, id)` 已有；**但没有一个工具消费它**（`grep "resolveSecret" apps/server/src` 只有定义处）
- 暴露给模型的 17 个工具里**没有任何执行能力**（无 shell / 无 exec / 无 git）
- `computer.ts` 有 `execute()`，但后端是 `spawn("docker", …)`，而本机 **docker 不可用** ⇒ 实际跑不起来

**做法（拆两小步，安全边界不一次放开）**

**2a 接线机制（不新增执行能力，先做）**
- 任务创建时按需铸凭据：`createTask` 的入参加 `credentials?: {label,kind,scopes,ttlMs}[]`
  → 铸好后把 **id** 记进 `task.state.credentialIds`（**state 里只放 id，绝不放明文**）
- 工具上下文加一个访问器：`TaskContext.secrets.get(id) → resolveSecret(...)`，
  **每次调用都重新校验**（已吊销/过期就抛可续接提示）
- 脱敏护栏：工具结果、事件、日志里只允许出现 `…后6位`；加一条**回归测试**断言
  日志/事件文本里匹配不到 `secret` 明文

**2b 第一个消费者：git 工具（依赖 ③ 完成后做）**
- 新增参数化工具（**不是** `run_command`）：`git_commit(repo, message)` / `git_push(repo, remote?)`
  —— 只允许固定动作，不接受任意命令；`repo` 必须在沙箱工作区内
- 凭据注入方式：`GIT_ASKPASS` 指向一个临时脚本 + `GIT_USERNAME`/`GIT_PASSWORD` 经 **env** 传入，
  **不写进 repo config、不进命令行参数**（`ps` 会看到）；用完即删临时脚本
- 任务终态钩子已能吊销（现有 ✓）

**验收（三步都要看得见）**
1. 建一个测试仓库 → 铸一把 `repo:write` 凭据 → 派一个 `git_push` 任务 → **推送成功**
2. 任务终态后查凭据：`revokeReason=task_finished`
3. 用同一把凭据**再推一次 → 失败**（证明"销毁"不是摆设）
4. 越权测试：换个不在沙箱内的仓库路径 → 工具拒绝

**风险**：这是本项目**第一次**让模型有"改外部世界"的执行能力 → 必须与 ③ 同时上线，且只给参数化动作。

**工作量**：2a 半天；2b 1–2 天（含沙箱对接）。

## ③ 沙箱"任务结束即重置"

**目标**：每个任务有一个**一次性工作区**，任务一结束：进程停掉、目录删除、凭据吊销。
（= Muse `ConfidentialVmProvisioningReset.reset()` 的语义，我们用能用的手段等价实现。）

**现状（证据）**
- `apps/server/src/computer.ts`：后端 `spawn("docker", …)`（第 66 行）→ 本机 `docker ps` **不可用** ⇒ 沙箱是坏的
- 本机 **无 `/dev/kvm`** ⇒ 上不了 Firecracker/microVM
- 但 `bwrap` ✓ / `systemd-run` ✓ / `unshare` ✓ 都在 ⇒ **非特权隔离可行**
- 任务的私有状态已经有位置：`task.state.*`（browserId / sessionId / failures …）

**做法**
1. **把执行后端抽象出来**：`SandboxBackend` 接口（`start / exec / write / read / stop / destroy`），
   先实现 `bwrap` 后端；`computer.ts` 的 `execute()` 改为走它（Docker 后端保留但默认不启用）
2. **一次性工作区**：`$DATA_DIR/sandboxes/<taskId>/`
   - 只读挂载 repo；只有 workspace 可写；**默认无网络**（需要时给域名白名单）
   - 资源上限：`systemd-run --user --scope -p MemoryMax=… -p CPUQuota=…` + `timeout` 墙钟上限
   - 环境变量最小化（**不继承** server 进程的 `.env`）
3. **生命周期**：建任务 → 建沙箱 + 写 `task.state.sandboxId`；任务终态 → `stop` → **删目录** → `revokeForTask`
   → 写一条任务事件「沙箱已重置」（与已有的凭据吊销挂在同一个钩子里）
4. 平台侧：沙箱状态进 `/api/agent`；App 的 computer 面板显示"运行中 / 已重置"

**验收（每条都要真的跑）**
- 跑一个会写文件的任务 → 终态后 `$DATA_DIR/sandboxes/<taskId>` **不存在**，事件里有「沙箱已重置」
- 沙箱内 `curl https://example.com` **失败**（默认无网）
- 沙箱内读 `/home/ubuntu/openmuse/.env` **失败**（越界防护）
- 沙箱内 `cat /proc/self/environ` **看不到** server 的密钥
- 资源上限：一个死循环任务被墙钟/内存上限杀掉，且**不影响**其他任务

**风险**：bwrap 的可用性依赖内核 unprivileged user namespace（本机已验 ✓）；
若将来要跑不可信代码 / 并发多个编程任务 / 给别人用 → 那时再上独立沙箱主机（gVisor/Firecracker，需 KVM 机型）。

**工作量**：2–3 天。

## 顺序、依赖与"明确不做"

```
① 凭据 App 管理页   （独立，先做，用户立刻看得见）
②a 凭据接线机制      （独立，纯服务端，无新执行能力）
③  沙箱重置          （②b 的前置）
②b git 工具          （第一次对外执行；必须与 ③ 同时上线）
```

**总工期估计**：① 0.5 天 → ②a 0.5 天 → ③ 2–3 天 → ②b 1–2 天（可并行 ③）。

**明确不做（以及原因）**
- Muse 的 **attestation / Noise 原生信道**：依赖它的 KVM 与硬件证明体系，我们没有对应基础设施；硬做是空转
- **Confidential VM**：本机无 `/dev/kvm`，microVM 上不了
- **给模型任意 shell / run_command**：只给**参数化动作**（git_commit / git_push），
  这是本项目安全边界的关键一条 —— 一旦放开任意命令，② 的凭据隔离就形同虚设
- 在 ③ 完成之前**不**上线 ②b

**一句话**：① 让人看得见，② 让人用得上、且用完就没了，③ 保证那时候**没有别的路径能绕过它**。
